# 限流与重试

限流用于保护平台和上游服务的稳定性。实际限制会因账户、模型和运行状态而不同，以接口响应和控制台信息为准。

## 识别限流

HTTP `429` 通常表示请求频率或并发超过当前允许范围。不要把所有错误都当成限流；认证、权限和模型错误需要分别处理。

## 指数退避

重试时逐步增加等待时间，并加入少量随机抖动，避免多个请求在同一时刻再次拥塞。

```text
第 1 次重试：约 1 秒后
第 2 次重试：约 2 秒后
第 3 次重试：约 4 秒后
```

## 重试边界

- 设置最大重试次数和总超时时间。
- 只自动重试临时性错误。
- 对可能产生副作用的请求谨慎重试。
- 长时间异常时停止请求并向用户显示清晰状态。

## 降低并发

批量任务应使用队列限制同时运行的请求数。稳定的低并发通常比大量请求失败后反复重试更高效。
