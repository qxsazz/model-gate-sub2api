## 已修复

| 优先级 | 问题与触发条件 | 影响与修复 |
| --- | --- | --- |
| P1 | 已登录用户提交低压缩体积、高像素尺寸的头像，进入自动压缩 | 原先在检查像素数之前调用 `image.Decode`，可分配远大于 100KB 文件限制的像素缓冲。现在先读图片头，限制单边 4096、总计 4MP，再完整解码；base64 解码前也检查编码长度。回归使用大尺寸 PNG 头验证，未运行会耗尽内存的旧版解码。 |
| P1（依赖告警） | 画布实际 npm 锁文件落后于已有安全升级，主站构建工具及导出库也有已知漏洞版本 | 画布生产依赖原有 2 项 critical、17 项 high；主站全部依赖原有 3 项 critical、35 项 high。已更新兼容修复版本，包括 Axios、DOMPurify、Router、PrismJS、KaTeX，以及 Vite/Vitest 和其传递依赖。告警数量不等于项目存在同等数量的可利用漏洞。 |
| P2 | gzip/deflate/zstd 请求解压超过 64MB | `LimitReader` 原先把超限数据截断并作为成功结果返回。现在检测额外一字节，超限返回可识别的大小错误，不返回部分正文、不改成功解压元数据；同时限制 zstd 解码内存、窗口与并发。 |
| P2 | 安全工作流没有检查实际部署的画布依赖 | 新增独立 `canvas-security`，按 Docker/前端 CI 实际使用的 `package-lock.json` 安装并审计生产依赖，扫描失败或 high/critical 告警会阻止检查通过。 |
| P2 | 主站依赖扫描返回网络错误 JSON 或缺少结果详情 | 原脚本在没有 advisory 时直接通过；本地模拟 `ECONNRESET`，旧脚本退出 0。现在校验扫描结果结构、计数及错误字段，同一输入退出 1，并增加 CLI 回归。 |
| P2 | 刷新账号凭证的兼容路径遇到迟到成功，CPU 忙时 context 定时取消信号尚未发布 | 全量测试暴露原有 `LateSuccessPastAttemptDeadlineIsRejected` 偶发失败。现在统一 API 与兼容路径共用实际截止时间检查，在写凭证前检查已过期的 deadline；已成功持久化、仅清理超时的结果仍保留原有成功语义。 |

## 仍需记录的边界

1. 开发工具中的 `postcss-selector-parser@6.1.3` 有 `GHSA-rj75-hqrm-r3gf` 中风险 CSS 解析耗时问题，来源为 ESLint/Tailwind 构建链；不在生产依赖中。修复版本为 7.1.6 及以上，跨主版本升级应随 ESLint/Tailwind 兼容改造完成，本次没有用豁免掩盖该项。
2. 原有冷 Key 同时查询超过认证并发保护时，仍可能在进入网关前返回 `API_KEY_AUTH_OVERLOADED`；本次不改正常调度及认证容量策略。取消后的分离上游请求也可能继续占实际连接，见网关压测报告。
3. 自动扫描和抽查不能证明不存在逻辑漏洞；本次未做生产渗透、完整历史密钥审计、多实例长时间故障测试或完整数据竞争检测。配置、部署网络、第三方服务与未来依赖公告仍会影响安全性。
4. 本地前端构建在主动限制 Node 堆为 1.5GiB 时出现 V8 内存不足；提高至 3GiB 后构建通过。同步提高备用 `deploy/Dockerfile` 的前端构建堆上限，仅影响构建阶段；本轮没有为所有备用 Docker/容器部署变体分别构建镜像。
