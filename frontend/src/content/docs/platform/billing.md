# 计费与用量

把一次调用的模型、用量和有效倍率放在一起看，才能理解实际扣费。

## 费用从哪里来

不同模型可能分别计量输入、输出、缓存写入、缓存读取，图像或其他能力也可能有独立计量方式。不要把所有 Token 都按同一单价相乘。

模型计量费用与分组有效倍率共同影响扣费；人工定价或其他计费规则可能优先适用。最终以使用记录中的实际费用为准。

## 倍率计算示例

假设一次请求的标准计量费用为 `$10`，普通分组基础倍率为 `0.30`：

| 场景 | 有效倍率 | 示例费用 |
| --- | --- | --- |
| 未参与减免 | 0.30 | $3.00 |
| 减免 0.03 | 0.27 | $2.70 |
| 减免 0.075 | 0.225 | $2.25 |

这里减免的是倍率值，`0.03` 不等于优惠 `3%`。普通组成长减免最高为 `0.075`，小倍率组的既有规则保持不变。分组还可能设有倍率下限，最终倍率不能低于下限。充值加赠会影响实付购买能力，但不再次改变记录中的扣费倍率；详见 [VIP 等级与权益](/docs?cat=membership&page=vip)。

## 核对使用记录

按时间范围、模型和密钥缩小查询，关注请求状态、输入输出、缓存与实际费用。不同客户端的一次任务可能调用模型多次，不能把一个任务等同于一个请求。

## 管理成本

- 为不同应用创建独立密钥，便于核对和停用。
- 控制上下文长度、输出长度和自动重试次数。
- 限制批量任务并发，及时停止异常循环。
- 核对缓存记录，不把缓存量重复加入原始输入量估算。

本页示例不构成固定价格承诺。当前模型、分组价格及有效权益，以控制台和实际记录为准。
