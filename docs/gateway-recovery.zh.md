# 网关优先恢复

## 综合测试版本

`0.2.18-mg.2` 将官方 v0.2.18 升级、Gemini 画布模型列表兼容修复和本恢复策略合在同一测试版本中。通过现有 staging 发布流程部署，生产发布仍需后续指示。

综合验收包含 Responses、Chat Completions、Messages 三种 HTTP 协议的模拟上游 502/503 换号成功，以及 WebSocket 首次暂时无号、502、503 后恢复；同时保留 Gemini 列表规范化与画布模型发现回归。故障模拟使用测试上游，不向真实账号注入故障或调用付费生成。

部署工作流会在实际应用容器中校验 `GATEWAY_RECOVERY_ENABLED=true`，仅输出七个非敏感恢复配置值和二进制版本，确认部署后的策略确实启用。最终以部署日志中的源码 revision 和镜像 digest 确认版本，不只依赖版本字符串。

文本推理请求在尚未输出正文、思考内容或工具调用时，优先利用现有刷新凭证、切换账号和安全重试路径恢复可恢复故障。恢复不改变用户请求的模型，不绕过分组、模型权限、利润门、配额、风控或计费校验。

## 故障处理

| 故障 | 行为 |
| --- | --- |
| 首次选号失败，但存在支持该模型的活跃账号，暂时限流、过载或繁忙 | 网关退避等待并重新选号，不立即向用户返回 503 |
| 上游暂时性 429、500、502、503、504 | 在现有错误分类允许切换且输出可安全重试时，重试或切换账号 |
| 单个上游账号凭证失效 | 保留服务层刷新凭证机制；仍失败则排除该账号，尝试其他账号，不通过轮询重新启用失效账号 |
| 用户余额不足、权限不符、请求错误、模型确实不支持 | 保留原有明确错误，不增加恢复等待 |
| 空账号池、总配额耗尽、数据库诊断失败 | 不凭空假设可恢复，不增加选号等待 |
| 已输出正文、思考内容或工具调用 | 保留协议及上游安全边界，不自动重放 |

是否可以切号仍由 `UpstreamFailoverError` 的动作、作用域和绑定标志决定，HTTP 状态码本身不会覆盖禁止重试的决定。仅显式暂时性错误允许已失败账号在退避后再次成为候选；账号级重试次数、错误专用次数及截止时间继续生效。OAuth 429 和上游续接保护继续生效。

## 配置

`gateway.recovery` 默认启用，也可通过以下环境变量配置（Compose 已透传）：

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `GATEWAY_RECOVERY_ENABLED` | `true` | 改为 `false` 恢复原有重试策略 |
| `GATEWAY_RECOVERY_BUDGET_SECONDS` | `300` | 单请求或单轮恢复准入窗口 |
| `GATEWAY_RECOVERY_SELECTION_WAIT_SECONDS` | `120` | 累计选号及账号槽位等待上限 |
| `GATEWAY_RECOVERY_MAX_ATTEMPTS` | `12` | 发生可切换上游故障的尝试上限，包含首次失败 |
| `GATEWAY_RECOVERY_MAX_WAITERS` | `256` | 单实例恢复等待上限 |
| `GATEWAY_RECOVERY_MAX_WAITERS_PER_GROUP` | `64` | 单实例内每分组恢复等待上限 |
| `GATEWAY_RECOVERY_MAX_WAITERS_PER_USER` | `2` | 单实例内每用户恢复等待上限 |

恢复预算决定是否允许开始下一次恢复，不是整个请求的硬超时；已开始的上游调用仍使用现有超时，正常长回答不会因恢复窗口到期被截断。客户端取消会结束等待。等待上限以实例为单位，不替代原有 Redis 用户并发与账号等待队列限制。队列满或恢复耗尽后仍可能返回错误。

选号等待使用 1、2、4、8 秒退避并加随机抖动；上游 `Retry-After` 可推迟已失败账号的重新准入。流式选号/重试等待每 10 秒发送 SSE 注释心跳；账号并发等待使用原有协议心跳。只有心跳时仍可安全恢复，恢复耗尽按请求协议写终止错误，不能用 HTTP 200 心跳掩盖失败。

## 长会话与重放边界

普通 HTTP 会话的每个请求都有独立预算。WebSocket 成功完成一轮后，下一轮重新设置预算及故障计数；重试同一轮不会重置上限。WebSocket 是否能够更换账号和重建当前轮，仍由原有安全重放检查决定，不能承诺所有有上游状态的连接都可无感切号。

生图、显式图片生成工具、Gemini 生图、Gemini `cachedContent` 绑定及 OpenAI 原生 `previous_response_id` 绑定请求保留现有恢复边界，不扩展自动重试，以避免重复任务或破坏绑定状态。

即使尚未向用户输出内容，上游也可能已经执行请求或产生用量；自动恢复可能增加上游调用成本。

## 验证与运维

单元测试覆盖首次短暂无号后成功、失效账号隔离并切换、503 后健康账号接管、模型不支持立即返回、恢复预算/取消/队列限额、账号并发等待、心跳后的协议错误及输出后的禁止重放。配置、处理器及服务层完整测试也应通过。

结构化日志 `gateway.recovery_wait` 记录等待轮次、时长和失败次数；释放恢复等待名额时输出 `gateway.recovery_finished`，该日志只表示退出等待队列，不代表推理成功，最终结果以原有请求日志、流式错误记录及计费记录为准。

上线时需确认客户端、CDN、负载均衡及反向代理的超时允许较长等待。非流式请求不能通过发送 SSE 心跳维持连接，网关内部恢复也不能阻止外部代理因自身超时生成 502/503/504。可先在测试环境观察成功率、首字延迟、恢复耗尽率及等待队列大小，再调整预算。
