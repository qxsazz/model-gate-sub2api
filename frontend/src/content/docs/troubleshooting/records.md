# 查看记录与反馈问题

调用结果、计费用量、错误记录和网站操作日志各有用途，不能互相替代。

## 用户端查看路径

| 位置 | 用途 |
| --- | --- |
| 使用记录 `/usage` | 按时间、密钥、模型等核对调用与实际用量 |
| 使用记录中的错误记录页签 | 在平台开放该入口时查询自己可见的失败请求 |
| 渠道状态 `/monitor` | 在入口开放时查看可见渠道的状态，不代表每个请求都会成功 |
| 我的订单 | 核对支付订单，不用模型错误日志判断付款是否完成 |
| VIP 中心 | 核对累计有效充值、实际权益与奖励状态 |

**错误记录入口由平台开关控制。** 未看到页签，或收到 `Error requests view is disabled` 的 403，可能是该功能未开放，不是该用户全部模型调用都被禁止。

## 查询错误记录

1. 在使用记录页面选择发生错误的时间范围，核对本地时区。
2. 若错误记录入口已开放，切换该页签。
3. 按密钥名称、模型、错误分类和状态码缩小查询。
4. 打开对应详情，查看对用户开放的消息、入口、时间与上游状态等信息。

项目提供当前用户归属校验和受限记录视图，不向用户开放内部上游账号等管理字段。请求 ID 如由客户端或响应提供，可用于平台进一步关联查询；用户详情页面不保证包含全部内部追踪字段。

## 找不到对应记录

| 可能原因 | 下一步 |
| --- | --- |
| 日期或时区不一致、过滤条件过窄 | 扩大时间范围，暂时清除模型和状态过滤 |
| 请求未到达平台 | 查看客户端网络错误、代理和 DNS |
| 凭据无效、未能关联到用户 | 保存原始响应与请求 ID，向平台反馈 |
| 用户错误记录功能未开放 | 按实际页面入口和说明处理 |
| 记录尚未展示或超出保留范围 | 保留客户端证据，反馈时说明时间与时区 |

记录为空不等于请求成功，也不保证没有费用；先结合原始响应、用量及实际余额判断。

## 区分三类记录

**使用记录**用于核对调用用量与计费；**错误记录**用于排查失败请求；**操作日志**记录网站相关操作，属于管理端能力，普通用户不应被要求到后台查日志。

错误状态不等于零用量。例如流式输出中断，可能已有部分生成内容；是否计费以实际使用记录为准。

## 请求 ID 与响应

项目在正常请求处理链路中提供 `X-Request-ID` 响应头。客户端支持查看响应头时，可以保存这个值；若请求在代理或网络层提前失败，可能无法取得它。

不同入口可能使用外层 `message` / `reason`，或嵌套 `error.code` / `error.type` / `error.message`。完整、经过脱敏的错误正文比只提供“报了 403”更有助于定位。

## 安全反馈模板

```text
发生时间与时区：
客户端与版本：
请求入口（删除 URL 中的凭据参数）：
模型与分组：
密钥名称（不要填写完整密钥）：
HTTP 状态 / 是否有响应：
错误业务码与脱敏消息：
请求 ID（如有）：
是否流式 / 是否产生部分输出：
使用记录与错误记录是否可见：
已经尝试的排查步骤：
```

不要提供完整 API Key、Authorization、Cookie、刷新 Token、密码、私人提示词或付款敏感信息。详见 [安全与隐私底线](/docs?cat=about&page=security)。
