# VIP 等级与整套权益

## 管理方式

保留「等级与规则」「分组权益」「用户权益」三个栏目。等级阶梯增加普通会员及 VIP1–5 的每日签到金额，数据与签到后台使用同一个 `achievement_daily_policy`，保存同步更新历史政策。

用户权益支持搜索用户名或邮箱，也可按 ID 查询。管理员选择普通会员或 VIP1–5、可选到期时间和操作原因，确认后统一应用该等级的全部配置权益。既有到期时间回填，未修改时保留原精确时间。

指定等级是精确覆盖，并非最低等级：实际充值成长为 VIP5 的用户指定 VIP1 后，以 VIP1 权益生效；到期或恢复自动后按真实充值记录计算。VIP 总开关关闭时，普通会员权益生效，指定记录保留等待开关开启。

## 一致性边界

- 有效等级统一用于会员显示、签到档位、普通组优惠、专属组准入、邀请返利和新订单充值加赠。
- 并发及 RPM 沿用原等级规则的保障目标，不降低更宽松的基础账号额度；私人、订阅、测试分组不由 VIP 自动授予，原有手工授权和定制价保留。
- 指定等级或恢复自动会清除旧 VIP 单项覆盖，保留审计；使用统一等级后的账户不能通过兼容接口新增单项覆盖。
- 指定等级不写入充值本金、余额或充值成长流水，不自动发放充值达标奖。已有订单报价、佣金快照和签到回执不重算。
- 改级影响后续新请求和新订单；鉴权缓存失效，已执行请求保留原报价。
- 充值成长等级与有效等级分别展示，用户 VIP 中心不把管理员指定写成已累计充值达标。

## 历史与补签

迁移253新增 `vip_user_level_history`，记录指定、恢复、到期时间、操作者和原因。历史补签沿用北京时间该日截止前的政策与充值记录，并应用当日有效的指定等级；恢复和降级不改写历史金额。期限正好在次日零点结束时，前一天仍按有效指定等级核验。

## 接口

| 方法 | 路径（/api/v1） | 参数 |
| --- | --- | --- |
| PUT | `/admin/vip/users/:id/level` | `level`0–5、`expires_at`可空、`reason`3–500字 |
| DELETE | `/admin/vip/users/:id/level` | JSON `reason`，恢复自动并清除旧单项覆盖 |
| GET/PUT | `/admin/vip/rules` | `daily_rewards`为普通会员及五档 VIP 的六个金额 |

写接口使用管理员权限及既有二次认证，数据库再次核验有效管理员和目标账户。金额配置须为六个有限非负值，每档不超过1000；共享金额策略与配置审计同事务提交。

## 验收

验证零充值指定高等级、真实高充值指定普通会员、到期与恢复自动、并发/RPM及分组变化、返利与充值加赠、签到即时到账、历史补签、既有回执不变、不同用户与无权限拒绝、两个配置入口一致性和临时等级精确到期时间保留。生产不发布，先在测试环境验收。
