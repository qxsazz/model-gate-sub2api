# MODEL-GATE 用户端高级控制台视觉统一设计

## 1. 背景

当前 `/home` 已经形成了明确的 MODEL-GATE 品牌视觉：珍珠白背景、深色品牌字、浅金色网络节点和克制的蓝色功能强调。登录后的用户端路由仍主要使用通用管理台样式，页面之间的视觉语言不够统一。

本设计将只改造普通用户端的前端视觉层和交互呈现，不修改后端、数据库、API 契约、鉴权逻辑或管理员 `/admin/*` 页面。

## 2. 目标与非目标

### 2.1 目标

- 让 `/dashboard`、`/keys`、`/usage` 等用户页面与 `/home` 共享同一品牌语言。
- 保留当前左侧可折叠导航、顶部工具栏和所有现有路由。
- 建立可复用的颜色、字体、间距、卡片、表格、按钮、状态和空状态规则。
- 强化“高端奢侈但可工作的 AI API 控制台”气质。
- 保证数据密集页面仍然清晰、可扫描、可操作。
- 保持移动端可用，不引入持续高频动画或明显性能负担。

### 2.2 非目标

- 不修改后端代码、数据库迁移、API 请求结构或响应结构。
- 不改变用户端路由名称、路径、权限和业务流程。
- 不重新设计管理员 `/admin/*` 页面。
- 不新增独立前端 artifact、独立部署或新的构建链路。
- 不在本阶段新增业务指标、报表字段或收费功能。

## 3. 已确认的设计方向

### 3.1 品牌方向

采用“珠宝杂志感 / 高级编辑感”的视觉方向。核心是把首页的网络节点概念转译成控制台中的细金线、节点和状态边界，而不是把页面做成金色背景或装饰性海报。

视觉关键词：

- 香槟淡金
- 黑曜石
- 珍珠白
- 细边界
- 低圆角
- 宽留白
- 安静的数据层级
- 低频、短时的交互反馈

### 3.2 颜色令牌

| 令牌 | 建议值 | 使用范围 |
| --- | --- | --- |
| `ink-950` | `#121316` | 侧边栏、主按钮、深色文字 |
| `ink-900` | `#24252A` | 标题、正文重点、表格主要内容 |
| `gold-500` | `#C9B477` | 品牌节点、指标顶线、图表主线、当前导航边界 |
| `gold-700` | `#9C8344` | 金色文字、深色背景上的金色细节 |
| `pearl-50` | `#FBFAF7` | 页面工作区、主背景 |
| `champagne-50` | `#F5F1E7` | 指标卡、筛选栏、表头和辅助区域 |
| `line-warm` | `#E7E1D4` | 页面和组件边框 |
| `status-success` | `#52816D` | 成功、正常、健康状态 |
| `status-warning` | `#947535` | 额度提醒、等待和需要注意的状态 |
| `status-danger` | `#A75D56` | 失败、异常和高风险操作 |

蓝色不再作为用户端的主视觉色，只在需要表达链接、焦点或兼容现有功能语义时保留，避免与首页的香槟金品牌识别冲突。

### 3.3 字体系统

| 层级 | 字体 | 使用范围 |
| --- | --- | --- |
| 英文品牌/展示标题 | `Bodoni Moda` | MODEL-GATE、英文页眉、空状态展示标题、品牌短句 |
| 中文页面标题 | `Noto Serif SC` | 页面标题、重点中文标题、重要空状态 |
| 中英文正文与控件 | `Noto Sans SC` | 导航、按钮、表格、筛选器、说明文字、表单 |
| 技术数字 | `DM Mono` | API Key、模型名、Token、指标数字、代码、版本和时间戳 |

字体使用边界：Bodoni Moda 不进入密集表格、长正文和小尺寸操作控件；技术数据使用等宽字体或 `tabular-nums`，保证数字列稳定对齐。正式实现需要确认字体加载方式，优先使用仓库可控的本地字体资源或明确的构建时字体方案，避免运行时依赖第三方字体请求。

## 4. 共享应用外壳

### 4.1 导航

- 保留当前 `AppLayout`、`AppSidebar` 和 `AppHeader` 的职责边界。
- 侧边栏使用黑曜石底色，当前条目使用香槟金细边界和低透明度金色底。
- 侧边栏品牌标记统一使用黑底、香槟金细边框和金色 `MG` 字标，不使用大面积渐变。
- 展开状态显示完整 `MG` 图标、站点名称和版本号，Logo 固定为 `48 x 48px`。
- 折叠状态仍使用同一个完整 `MG` 图标，不切换为其他简写或图形，Logo 固定为 `44 x 44px`。
- 品牌标题区域高度统一为 `72px`；折叠状态在 `72px` 侧边栏中保持图标水平居中。
- `MG` 字标在 `256 x 256` SVG 画布中使用约 `96px` 字号，并缩小边框内留白，保证小尺寸下仍有清晰品牌识别。
- Logo 继续读取现有 `site_logo` 配置；后台上传同一资源即可覆盖展开和折叠状态，不新增后端字段。
- 折叠状态只保留图标、当前状态和 tooltip；展开状态保留现有分组、功能开关和子菜单行为。
- 移动端继续使用抽屉导航，不新增另一套路由导航模型。

### 4.2 顶部工具栏

- 统一显示英文上下文标签、中文页面标题和一行说明。
- 页面级主操作放在标题区右侧；页面内筛选和刷新放到内容工具栏。
- 主题切换、用户入口和现有全局操作保持原有行为。
- 背景节点只出现在标题区右上或空白区，使用低透明度静态装饰。

### 4.3 页面容器

- 页面主体使用珍珠白背景和统一最大宽度。
- 内容区采用 `24px` 左右的桌面间距，移动端降为 `16px`。
- 页面模块之间保持明确分段，不将卡片嵌套在卡片中。
- 组件圆角默认约 `6px`，弹窗和少数状态容器可使用 `8px`。
- 阴影只用于弹窗、浮层和需要层级提升的内容，常规卡片使用细边框为主。

## 5. 用户路由设计

### 5.1 `/dashboard`

信息层级：欢迎与状态 -> 核心指标 -> 趋势 -> 最近调用 -> 快捷操作。

- 顶部标题：英文上下文 `OVERVIEW`，中文标题“控制台总览”，副标题说明当前 API 使用状态。
- 第一层指标：请求量、Token 用量、活跃密钥、错误率或当前已有指标，保持真实数据字段不变。
- 第二层图表：调用趋势和现有模型/平台分布组件，图表主线使用香槟金，功能状态色单独表达。
- 第三层内容：最近调用表格与快捷操作，快捷操作只突出真实高频动作。
- 加载、空数据和错误状态使用统一组件，不隐藏真实失败信息。

### 5.2 `/keys`

- 顶部标题：英文上下文 `ACCESS KEYS`，中文标题“API 密钥”。
- “创建密钥”是唯一高强调按钮，使用黑曜石底和浅色文字。
- 搜索、分组、状态筛选保持同一条工具栏，移动端允许换行。
- 端点说明独立为轻量信息区，避免与密钥表格混在一起。
- API Key、模型、端点和额度数值使用技术字体或等宽数字。
- 复制、刷新、列设置、更多操作使用图标按钮，并提供 tooltip 和键盘焦点状态。
- 密钥创建、删除、轮换等高风险动作沿用现有确认流程，仅改变视觉呈现。

### 5.3 `/usage`

- 顶部标题：英文上下文 `USAGE ATELIER`，中文标题“用量分析”。
- 时间范围、粒度和刷新操作组成统一顶部工具栏。
- 第一层保留当前用量统计卡片。
- 第二层保留模型、分组、端点和 Token 趋势图表，图表容器统一使用暖色边界和轻量标题。
- 第三层为筛选栏与明细表格，图表负责发现趋势，表格负责核对事实。
- 用量、错误请求等标签页使用统一的当前状态线，不使用厚重的彩色胶囊。
- CSV 导出、列设置、刷新和重置行为保持不变。

### 5.4 其他用户页面

`/profile`、`/subscriptions`、`/orders`、`/redeem`、`/affiliate`、`/available-channels`、`/monitor` 等页面复用同一套页面标题区、卡片、表格、工具栏、状态和空状态规则。每个页面只定义自己的数据内容，不再单独发明新的视觉语言。

## 6. 组件规范

### 6.1 按钮

- 主操作：黑曜石背景，浅色文字，小圆角。
- 品牌操作：香槟金填充，仅用于少量明确的品牌动作。
- 次要操作：珍珠白背景、暖色边框、深色文字。
- 图标操作：方形小按钮，必须提供 tooltip、焦点环和禁用状态。
- 不使用大面积蓝色渐变按钮。

### 6.2 指标卡

- 珍珠白或香槟白底。
- 顶部使用 `1-2px` 香槟金线标识重点。
- 标签使用无衬线字体，数值使用 DM Mono 或 tabular 数字。
- 趋势只使用状态色和简短变化说明。

### 6.3 表格

- 表头使用香槟白底和暖色下边界。
- 行使用细分割线和低对比 hover。
- 技术字段使用等宽字体，长文本保持截断和可展开能力。
- 移动端优先保证名称、状态、主要操作可见，其余字段按现有列设置能力折叠。

### 6.4 状态与反馈

- 正常：深绿色点和浅绿色背景。
- 警告：深金色点和浅香槟背景。
- 异常：砖红色点和浅红背景。
- 金色不承担错误语义，避免品牌色与风险色混淆。

### 6.5 空状态与弹窗

- 空状态使用虚线暖色边界、低透明度节点背景和简洁的衬线标题。
- 弹窗使用白底、暖色细边界和清晰的标题/正文/操作区。
- 危险操作沿用红色语义和现有确认逻辑。

## 7. 响应式与可访问性

- 先保证桌面控制台的密度和信息层级，再对移动端做折叠和重排。
- 侧边栏在移动端使用现有抽屉机制，页面主体不得被固定导航遮挡。
- 不使用依赖颜色才能理解的状态；所有状态同时提供文字或图标。
- 所有图标按钮保留 `title` 或可访问名称。
- 键盘焦点、禁用、加载和错误状态必须可见。
- 遵守 `prefers-reduced-motion`，装饰节点不使用持续高频动画。
- 颜色对比度需要在实际页面中使用浏览器审查工具复核，尤其是金色文字和浅色背景组合。

## 8. 实现边界与分阶段计划

### 阶段一：共享视觉基础

- 盘点现有 `AppLayout`、`AppSidebar`、`AppHeader` 和全局 `style.css` 的可复用类。
- 建立用户端专用颜色、字体、边框、阴影、间距令牌。
- 统一侧边栏、顶部标题区、按钮、状态、卡片、表格和空状态基础样式。
- 不改变任何 API、路由和数据逻辑。

### 阶段二：核心页面

- 依次改造 `/dashboard`、`/keys`、`/usage`。
- 优先只调整模板结构和样式绑定，不重写已有数据获取和组件业务逻辑。
- 对复杂图表和表格保留原有组件，先做容器、标题和工具栏统一。

### 阶段三：其余用户页面

- 按影响范围改造个人资料、订阅、订单、兑换、联盟和渠道页面。
- 发现重复样式时回收到共享组件或全局类，避免逐页复制。

### 阶段四：验证

- 运行前端类型检查、单元测试、现有 i18n 检查和生产构建。
- 对 `/dashboard`、`/keys`、`/usage` 做桌面和移动端截图对比。
- 验证 API Key 创建/复制/删除、筛选、刷新、导出、分页、主题切换和移动端导航等既有流程。
- 确认管理员 `/admin/*` 页面没有被用户端样式意外影响。

## 9. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 金色文字在浅背景上对比度不足 | 金色优先作为边框和装饰，正文使用黑曜石色；实际页面做对比度检查 |
| 展示字体进入密集数据导致可读性下降 | Bodoni Moda 只用于品牌和展示标题，技术数据使用 DM Mono |
| 全局样式改动影响管理员页面 | 优先使用用户端作用域和共享组件边界，改动后跑管理员相关测试 |
| 外部字体加载失败导致布局变化 | 实现阶段使用本地可控字体资源或稳定 fallback，并固定标题高度 |
| 视觉改造误触业务逻辑 | 保留现有 composables、API 调用、事件名、路由和测试选择器 |

## 10. 验收标准

- 用户端主要页面能一眼识别为 MODEL-GATE，而不是通用后台模板。
- `/dashboard`、`/keys`、`/usage` 使用同一套页面标题、卡片、工具栏、表格和状态规则。
- 香槟淡金是品牌强调色，蓝色不再主导页面。
- 标题、正文、技术数字和代码的字体职责清晰，没有大段难读的展示字体。
- 原有用户流程、接口、路由和数据内容不发生行为变化。
- 桌面和移动端无明显遮挡、溢出、文本重叠或布局跳动。
- 现有前端测试、类型检查和构建通过。
