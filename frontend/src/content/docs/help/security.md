# 安全与隐私 · 服务底线

保护访问凭据、尊重账户归属、减少不必要的信息暴露，是 MODEL-GATE 的服务底线。便利不应以公开你的密钥、代码或私人内容为代价。

## 凭据保护

- 正式接入使用 HTTPS，不为解决连接问题关闭证书校验。
- API Key 只应放在可信客户端或服务端，不嵌入公开网页、不提交到 Git 仓库。
- 为不同应用、设备和环境使用独立密钥，发现泄露后及时停用并核对使用记录。
- 平台排障不要求你在公开聊天或截图中暴露完整密钥。

## 账户隔离

用户用量和错误详情按当前登录账户校验归属。用户端错误记录采用受限字段视图，不提供内部上游账号、内部连接地址等管理信息。

你可能看到自己请求的客户端 IP、模型、分组和错误描述。分享这些记录前仍需脱敏，不应将自己的页面截图公开给无关人员。

## 清晰的数据边界

| 环节 | 数据处理边界 |
| --- | --- |
| 客户端 | 可能保存对话、读取文件、同步配置或上传诊断；由工具自身策略决定 |
| MODEL-GATE | 为完成转发、鉴权、计量与故障排查处理必要信息 |
| 模型上游 | 按对应服务的处理规则接收模型请求 |

使用统一网关不代表客户端或上游自动停止保存数据。敏感业务接入前，应分别确认这三个环节的适用政策。

## 必要记录与隐私保护

费用核对、运行排障与安全保护可能需要用量、错误及审计信息。我们强调必要信息和授权范围，不以未经核实的“绝不记录任何内容”“完全匿名”替代真实的数据边界。

具体记录范围、保留周期和删除安排，以正式隐私政策、运营配置及适用规则为准。本页不承诺未核实的存储加密方式或保留时限。

## 安全反馈问题

先提供时间、状态码、请求 ID、模型、分组和脱敏后的错误正文，不发送完整密钥、会话 Token、密码、银行卡信息或整个代码仓库。

如果日志包含认证头、URL 密钥参数、个人信息或私人正文，先删除这些字段。有关操作见 [查看记录与反馈问题](/docs?cat=troubleshooting&page=records)。

## 遇到异常访问

发现凭据泄露或非本人调用时，停止相关客户端、停用受影响密钥并检查记录。权限、IP 限制和安全策略不应通过绕过验证的方式处理；确需调整时，通过已有的授权管理流程完成。
