# Model-Gate 静态文档中心设计规格

日期：2026-09-11
状态：待用户最终评审
目标分支：`feat/model-gate-frontend`

## 1. 背景

Model-Gate 首页已经完成品牌化改造，但首页底部“文档”仍是占位链接。项目需要一个位于同一域名下的公开文档中心，让用户从首页进入后，可以通过章节目录阅读 Model-Gate 的接入、使用和计费说明。

参考站点仅用于借鉴文档中心的信息架构和交互方式。页面文案、代码示例、品牌元素和视觉表达全部针对 Model-Gate 原创，不复制第三方站点正文、图片或品牌素材。

第一阶段文档是随前端代码发布的静态内容，不提供管理员后台编辑能力。

## 2. 目标

- 在 `model-gate.cc` 同域名下提供公开文档中心。
- 只注册一个 `/docs` 公开路由，通过 `cat` 和 `page` 查询参数选择分类与文章。
- 提供桌面端左侧章节目录、正文区域和右侧页内目录。
- 提供适配手机和平板的响应式阅读体验。
- 使用 Markdown 维护正文，使文档易于审阅、提交和逐步修改。
- 突出 Model-Gate 品牌，而不是沿用 Sub2API 或参考站点的视觉身份。
- 不修改数据库、后端 API、用户权限、计费和生产业务逻辑。
- 尽量隔离定制代码，降低以后同步 Sub2API 上游版本时的冲突。

## 3. 非目标

第一阶段不实现以下功能：

- 管理员后台在线编辑、发布或删除文档。
- 文档数据库、历史版本、草稿和审批流。
- 用户评论、点赞或阅读进度同步。
- 全文服务端搜索或第三方搜索服务。
- 多租户文档和按用户权限显示不同文章。
- 对第三方文档内容进行全文复制。

未来如果文档更新频率显著增加，可以在不改变公开路由的前提下，将 Markdown 数据源替换为后端内容管理接口。

## 4. 用户体验与信息架构

### 4.1 单路由与查询参数

Vue Router 只注册一个公开路由：

```text
/docs
```

当前分类和文章通过查询参数表达：

| 地址 | 页面用途 |
| --- | --- |
| `/docs` | 使用默认分类和默认文章进入文档中心 |
| `/docs?cat=tutorial&page=quick-start` | 快速开始 |
| `/docs?cat=tutorial&page=api-key` | API Key 创建和安全使用 |
| `/docs?cat=tutorial&page=api-reference` | OpenAI 兼容 API 地址和请求格式 |
| `/docs?cat=clients&page=claude-code` | Claude Code 接入指南 |
| `/docs?cat=clients&page=codex` | Codex 接入指南 |
| `/docs?cat=clients&page=cursor` | Cursor 接入指南 |
| `/docs?cat=platform&page=rate-limits` | 限流、并发和重试说明 |
| `/docs?cat=platform&page=billing` | 余额、计费与用量说明 |
| `/docs?cat=help&page=faq` | 常见问题 |

文档页面不要求登录。用户切换左侧文章时仍停留在 `/docs`，仅更新 `cat` 和 `page`，因此不会产生大量 Vue Router 路由记录。

缺少参数时使用注册表定义的默认分类和文章；参数无效时显示文档专用的“页面不存在”状态，并提供返回默认文档的按钮。查询参数必须通过注册表白名单解析，不能直接拼接为文件路径。

### 4.2 桌面端布局

页面由四部分组成：

1. 顶部品牌栏：Model-Gate 标志、文档标题、返回控制台、主题切换。
2. 左侧导航：按“开始使用、客户端接入、平台规则、帮助”分组展示文章。
3. 中央正文：显示标题、摘要、更新时间、Markdown 正文、上一篇和下一篇。
4. 右侧页内目录：根据正文二级和三级标题自动生成，并高亮当前阅读位置。

左侧导航和右侧目录在滚动时保持可见，正文保持合适的阅读宽度，代码块支持横向滚动和一键复制。

### 4.3 移动端布局

- 顶部保留 Model-Gate 品牌和文档标题。
- 左侧导航折叠为抽屉菜单。
- 右侧页内目录折叠到“本页目录”。
- 正文占满可用宽度，代码块不撑破页面。
- 所有交互目标满足触屏点击尺寸要求。

### 4.4 首页入口

首页底部“文档”由占位链接改为站内链接 `/docs`。默认使用 Vue Router 导航，不打开新窗口。

首页顶部已有的文档入口也统一指向 `/docs`，避免用户配置为空时入口消失。原有可配置外部 `doc_url` 保留兼容能力，但 Model-Gate 默认值为站内文档地址。

## 5. Model-Gate 品牌设计

### 5.1 视觉方向

- 延续首页的深色科技感、粒子网络和渐变光效，但文档阅读区降低装饰密度。
- 主色使用 Model-Gate 现有的蓝紫渐变，强调色用于链接、当前目录和关键提示。
- 文档正文采用高对比度中性色，保证长时间阅读舒适度。
- 卡片、提示框和代码块采用统一圆角、边框和阴影体系。
- 页面明确显示 `MODEL-GATE DOCS`，不出现参考站点品牌。

### 5.2 内容语气

- 简洁、直接、面向实际接入任务。
- 先给出可执行步骤，再补充原理和注意事项。
- 示例域名统一使用 `https://model-gate.cc`。
- 示例密钥统一使用明显的占位值，例如 `mg_sk_example`，不得包含真实凭据。
- 不承诺未经验证的模型、价格、限额或可用性。

### 5.3 文档组件

正文支持以下品牌化组件：

- 信息、提示、警告和危险提示框。
- 带语言标签和复制按钮的代码块。
- 步骤列表和检查清单。
- 参数表格。
- 上一篇和下一篇导航。
- 返回控制台和创建 API Key 的行动按钮。

第一阶段优先复用标准 Markdown 语法。品牌提示框可通过受控的 Markdown 扩展语法实现，避免在 Markdown 中允许任意脚本。

## 6. 内容模型

### 6.1 Markdown 文件

文档正文位于独立目录：

```text
frontend/src/content/docs/
├── tutorial/
│   ├── quick-start.md
│   ├── api-key.md
│   └── api-reference.md
├── clients/
│   ├── claude-code.md
│   ├── codex.md
│   └── cursor.md
├── platform/
│   ├── rate-limits.md
│   └── billing.md
└── help/
    └── faq.md
```

每篇文章使用受控 front matter：

```yaml
---
title: 快速开始
description: 使用 Model-Gate 发起第一次 API 请求
section: 开始使用
order: 10
updatedAt: 2026-09-11
---
```

分类键和页面键由文档注册表显式指定。查询参数不直接转换成文件系统路径，避免路径穿越和不可预测的动态加载。

### 6.2 文档注册表

使用一个 TypeScript 注册表定义允许访问的分类、文档、导航分组和加载函数。页面只从注册表解析 `cat` 和 `page`。

注册表负责：

- 文档排序和分组。
- `cat + page` 到 Markdown 文件的映射。
- 上一篇和下一篇关系。
- 导航标题和页面元数据。
- 默认分类和默认文章。
- 对无效查询参数返回明确的未找到状态。

### 6.3 初始原创内容

第一版按以下顺序编写：

1. 快速开始：注册、登录、创建密钥、发送第一次请求。
2. API Key：创建、复制、轮换、撤销和安全建议。
3. API 接口：基础地址、认证头、常用兼容端点和错误处理。
4. Claude Code、Codex、Cursor：分别提供最小可运行配置和验证步骤。
5. 限流与重试：解释 RPM、TPM、并发和指数退避。
6. 计费：余额、用量、模型倍率及账单查看方式。
7. 常见问题：汇总接入失败、401、429、模型不可用和网络问题。

不确定的生产参数以明确占位标记管理，在发布前必须由实际系统配置验证，不能凭空填写。

## 7. 前端架构

建议新增：

```text
frontend/src/
├── views/docs/
│   ├── DocsView.vue
│   └── DocsNotFoundView.vue
├── components/docs/
│   ├── DocsHeader.vue
│   ├── DocsSidebar.vue
│   ├── DocsTableOfContents.vue
│   ├── DocsArticleNavigation.vue
│   └── DocsCodeBlock.vue
├── content/docs/
│   └── *.md
└── docs/
    ├── registry.ts
    ├── markdown.ts
    └── types.ts
```

职责划分：

- `DocsView.vue` 负责整体布局、响应式状态，并根据查询参数加载文章。
- 查询参数变化时只替换当前正文和导航状态，不卸载整个文档中心页面。
- `registry.ts` 是唯一的文档导航和文件映射来源。
- `markdown.ts` 负责 Markdown 渲染、标题 ID、页内目录和 HTML 清理。
- 组件只处理单一界面职责，避免形成一个超大的文档页面文件。

## 8. Markdown 渲染和安全

- 复用项目已有的 `marked`，不新增重复的 Markdown 渲染依赖。
- 复用项目已有的 `DOMPurify` 清理渲染结果。
- 禁止 Markdown 中的脚本、事件属性、iframe 和危险 URL 协议。
- 外部链接使用安全的 `rel` 属性；站内链接优先交给 Vue Router。
- 标题 ID 由确定性 slug 算法生成，并处理重复标题。
- 代码复制只复制当前代码块文本，不读取其他页面信息。
- 文档正文不包含真实 API Key、密码、服务器地址或内部运维信息。

## 9. 搜索策略

第一阶段不引入复杂搜索服务。文档数量较少时，左侧目录和浏览器页面查找足够使用。

如果需要轻量搜索，可以在第二阶段基于文档注册表生成静态索引，在浏览器中搜索标题、描述和正文摘要。公开路由和 Markdown 文件结构保持不变。

## 10. 后端、数据库与部署影响

- 不新增后端 Handler、Service、Repository 或 Ent Schema。
- 不新增数据库迁移。
- 不改变认证、用户、计费、密钥和网关逻辑。
- Vite 构建会将文档编译进现有前端静态资源。
- Caddy 继续使用现有 SPA 回退规则，使直接访问 `/docs` 返回前端入口文件。
- 部署仍采用当前 Sub2API 前端构建和后端嵌入静态文件流程。

上线前必须在生产等价环境验证直接访问和刷新 `/docs?cat=tutorial&page=quick-start` 不会得到 Caddy 404。

## 11. 与上游版本兼容策略

- 所有新页面放在独立的 `views/docs`、`components/docs` 和 `content/docs` 目录。
- 对上游文件的修改限制在路由注册、首页文档入口和必要的国际化键。
- 不修改依赖版本，除非实现阶段证明现有 `marked` 或 `DOMPurify` 无法满足需求。
- 为路由、注册表和 Markdown 渲染增加独立测试，便于上游合并后快速回归。
- 每次同步上游后优先运行文档测试、类型检查、国际化检查和生产构建。

## 12. 测试与验收

### 12.1 自动化测试

- `/docs` 能进入注册表指定的默认文章。
- 有效的 `cat` 和 `page` 能加载对应 Markdown。
- 缺少参数时能稳定使用默认值。
- 无效查询参数显示文档未找到页面，且不能加载任意文件。
- 切换文章后浏览器地址、当前目录高亮和正文保持一致。
- 导航分组、排序、上一篇和下一篇正确。
- Markdown 标题生成稳定且唯一的 ID。
- 危险 HTML 和 URL 被清理。
- 首页“文档”入口指向 `/docs`。
- 移动端导航抽屉可以打开和关闭。
- TypeScript、国际化检查和 Vite 生产构建通过。

### 12.2 人工验收

- 桌面、平板和手机布局可正常阅读。
- 深色和浅色主题下文字、链接、代码块对比度清晰。
- 直接访问并刷新任意有效的 `/docs?cat=...&page=...` 页面正常。
- 左侧目录、页内目录、上一篇和下一篇跳转正确。
- 代码块复制结果准确。
- 页面只显示 Model-Gate 品牌和原创内容。
- 文档内所有接口示例在测试环境验证后才允许发布。

## 13. 实施阶段

### 阶段一：文档框架

- 建立路由、布局、注册表和 Markdown 渲染器。
- 完成响应式导航、页内目录和代码块体验。
- 将首页入口连接到 `/docs`。

### 阶段二：原创内容

- 按栏目逐篇编写 Model-Gate 文档。
- 使用本地测试环境验证命令、URL 和操作步骤。
- 对暂未确认的生产参数保留显式审核标记，不发布猜测内容。

### 阶段三：质量与发布准备

- 完成自动化测试和多尺寸人工检查。
- 检查所有外部链接和代码示例。
- 验证生产等价构建及 SPA 路由回退。
- 单独提交文档功能，待用户确认后再决定是否合并到 `main`。

## 14. 成功标准

- 用户从首页一次点击即可进入同域名文档中心。
- 用户可以通过包含 `cat` 和 `page` 的稳定 URL 分享任意文档文章。
- 文档体验在桌面和移动端均清晰、易导航。
- 管理员无需后台功能即可通过修改 Markdown 更新内容。
- 第一版不产生数据库和后端业务风险。
- 定制代码与 Sub2API 上游结构保持清晰边界。
- 所有文档内容体现 Model-Gate 品牌且为原创内容。
