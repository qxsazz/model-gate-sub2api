# 成就系统累计实付充值准入与提示方案

日期：2026-10-30，America/New_York。状态：已在隔离分支实现，目标测试版本 `0.2.19-mg.3`；部署和验收进度以[测试 PR #62](https://github.com/qxsazz/model-gate-sub2api/pull/62) 的检查与发布记录为准，本文不是生产已生效规则。本次同时包含后端准入、前端提示与可回滚的合成验收，不授权生产部署、真实资金调整或历史奖励处理。

## 已确认范围

累计有效在线余额充值本金达到人民币 ¥10，开放签到、活动题目访问与答题、现金成就领取、系列奖励领取、补签卡领取和使用。允许多笔累计，扣除已确认退款；手续费、充值赠金、签到和活动奖励、普通管理员加余额不计入。正常消费至零不降低资格。

保留历史、成长、徽章及既有佩戴展示。充值入口、支付流程、普通 API、管理员审计独立可用。账号禁用优先，达标不解除账号限制。新准入不改变 VIP 和徽章本身的成长条件；现金开关、名单范围、预算、成就条件及终身领取唯一键继续叠加生效，达标不保证获得现金。

## 金额与确认事实

- 金额核验使用人民币分或数据库定点数，默认门槛 1000 分；不以浮点误差扩大资格。
- 新订单优先读取可信快照中的 `recharge_principal` 及币种。`amount` 可能含赠金或倍率，`pay_amount` 可能含手续费，不能直接视作人民币本金。
- 旧订单需定义可核验的本金还原规则。原方案核查称生产 109 笔未全额退款的已完成在线订单均为 easypay/alipay、缺 currency 快照；沿用 `PaymentOrderCurrency` 缺省 CNY 的兼容规则，不按当前汇率反算。该统计仍须在实施时复核。
- 非 CNY 订单只有可信且不可变的人民币等值本金快照时才计入，缺换算依据不按外币数值当人民币。
- 不复用 VIP 成长总额：币种、人工来源及历史覆盖范围不同。`admin_balance`、人工充值和历史回填不自动视为实付；承认线下实付另设有证据和审计的核验渠道。

每笔有效人民币本金＝该单已确认入账本金－已确认退款本金，限制在该单原本金范围内，再按用户累加。退款依订单实际退款单位与原本金比例换算，不能直接使用 `pay_amount - refund_amount`。

`refund_amount` 在申请及处理中也会写入，不能单独证明退款已完成。实施前须列明支付完成、退款确认、部分退款的权威字段和事实来源；保留已确认事实，不只靠当前 status 白名单。退款申请、处理中和失败期间不无依据将有效本金清零。待支付、未入账、支付失败不计；`PAID`、`RECHARGING` 或已付款但履约 `FAILED` 不因前端提示支付成功而提前开放，须按约定的可信入账确认纳入。

例：¥6+¥4 达标；本金 ¥9.99 加手续费后支付 ¥10 仍不达标；¥10 确认退款 ¥1 后重锁；余额消费为零仍达标。

## 后端授权与并发

统一资格计算，HTTP 预检查只改善提示，写操作必须在自身数据库事务内复核。现有成就写操作由 PostgreSQL 函数执行，新增迁移更新对应函数，不能只改 Go Handler。门槛不足要直接拒绝，不能只取消现金后继续写零元签到、尝试或通关记录。

实现前列明锁协议：成就函数常先锁配置、再锁用户；退款涉及订单、VIP 锁和用户锁。确认路径与资格核验须共享有效同步机制，包含无 VIP 快照旧单、管理员不扣余额的退款、异步退款确认。避免持有用户锁后反向等待退款已持有的订单锁。取得锁后按合适隔离级别重新读取资格事实，不复用旧快照。

两连接集成测试验证：退款先确认则领取拒绝且无副作用；领取先合法提交则保留回执，退款确认后锁定后续操作。支付、退款和领取重试不重复记账。

| 方法 | 路径 | 必要校验 |
|---|---|---|
| POST | `/user/achievements/checkin` | 写签到前事务复核，未达标不写零金额签到 |
| POST | `/user/achievements/claim` | 现金与卡片分流都复核 |
| POST | `/user/achievements/claim_series` | 系列领奖事务复核 |
| GET | `/user/achievements/card-preview` | 当前用户资格，不产生写副作用 |
| POST | `/user/achievements/use-card` | 扣卡、补签、到账事务复核 |
| GET | `/user/achievements/activity/topics` | 当前用户校验，不直接返回静态目录 |
| GET / POST | `/user/achievements/activity/:kind/:topic` | 读取校验，提交在写事务再次复核 |

其余用户成就入口逐项排查，佩戴和偏好不得成为发奖旁路。管理员主动发奖独立鉴权、原因、二次验证和审计，普通用户不能访问。

## 配置与接口契约

新增独立人民币门槛，默认 ¥10，不复用签到金额或 VIP 门槛。旧配置缺字段按 ¥10；旧管理页保存请求缺新字段时保留当前值，不因 Go 零值变成零门槛。当前仅允许大于 0、不超过 100 万元且精确到分的门槛，显式 0 不代表关闭。校验非有限数、负数和分精度，记录审计及 revision。

Snapshot 保留原记录并增加：

| 字段 | 含义 |
|---|---|
| `access_unlocked` | 本次后端核验的操作资格，不能当永久解锁标记 |
| `minimum_recharge_cny` | 当前门槛，单位人民币元 |
| `qualified_recharge_cny` | 扣除已确认退款后的合格本金 |
| `remaining_recharge_cny` | 后端计算的非负资格缺口 |
| `access_reason` | 稳定机器原因，区分达标、不足、账户不可用和核验失败 |

原因包括 `eligible`、`recharge_required`、`recharge_refunded`、`payment_pending`、`account_unavailable`、`verification_unavailable`。退款及支付处理原因由后端确认事实给出，前端不得自行推测。

未达标返回 HTTP 403 和 `ACHIEVEMENT_RECHARGE_REQUIRED`，包含当前资格金额；数据库异常在 Go `achievementError` 映射，不能落成通用 500。禁用账号返回账户不可用。核验未知或失败禁止发奖，返回可重试错误（如 503），不能伪装成充值 ¥0 或要求用户为核验失败再次付款。历史尽可能独立展示，不阻断正常支付入口。

## 成就系统提示与充值入口

提示位于账户概览与成就分类之前，支持窄屏、深浅色和屏幕阅读器。人民币统一用 `¥` 与两位小数，与美元奖励、VIP 成长区分。门槛和差额按后端结果展示，不写死 ¥10、不从余额推断。

| 状态 | 提示文案 | 操作 |
|---|---|---|
| 确认未达标 | **充值解锁签到与成就奖励**。累计有效在线充值满 ¥{minimum} 后，可使用签到、答题活动、成就领奖和补签卡。当前有效充值 ¥{qualified}，还差 ¥{remaining}。 | `去充值`、`已充值，刷新资格` |
| 支付完成但资格尚未确认 | 支付结果正在确认，请稍后刷新资格。仅到账确认后的有效充值计入门槛，请勿重复支付。 | 刷新资格，不提前解锁 |
| 确认退款后不足 | 当前有效充值已扣除确认退款，尚未达到 ¥{minimum} 门槛。相关操作暂不可用，历史记录保留。 | 显示实际缺口及充值入口；只有后端有确切原因时显示退款特定文案 |
| 核验失败或关键金额缺失 | 暂时无法核验充值资格，相关操作暂不可用。请稍后重试，无需为此次核验失败重复充值。 | `重新核验`，不虚构差额 |
| 确认达标 | 有效充值门槛已满足；奖励仍需符合账户状态、活动规则、现金开关、预算和领取记录。 | 恢复满足其余条件的操作，不承诺必得现金 |
| 账号禁用 | 当前账户不可使用相关功能，请联系管理员核查。充值不会解除账户限制。 | 不把充值当作解除禁用的方法 |

规则说明：

> 有效充值仅统计已确认到账的在线余额充值本金，允许多笔累计，扣除已确认退款。手续费、充值赠金、签到和活动奖励、管理员赠送不计入；正常消费余额不会影响资格。达到门槛不代表一定获得奖励，仍需满足对应成就和发奖规则。

充值入口沿用 `/purchase`，不新增支付接口，不擅改充值限额。“还差金额”是资格缺口，不代表充值页允许的最低下单金额。支付成功只能触发重新查询，不能由前端直接解锁；返回页面重新拉取 Snapshot，提供手动刷新。旧页面收到门槛 403 后刷新资格并保留历史。

锁定时禁用签到、现金/卡片/系列领取、题目访问、答题、补签预览与扣卡；保留历史、徽章介绍、成长及佩戴。旧后端未返回资格字段时维持原行为，不制造门槛已生效的提示；后端明确受限但数据不完整时不开放操作。

## 历史、退款与发布边界

迁移 `259_achievement_recharge_access.sql` 新增资格函数、用户入口校验及确认退款镜像表 `achievement_access_refunds`，不修改既有支付/退款状态机。确认退款使用单调保留的订单退款单位，以原本金比例换算；旧确认退款从终态订单及已有成功审计回填，不把处理中金额计作已退。

旧人民币无本金快照订单，按当时手续费“向上取整到分”的函数求唯一整分本金并回验，不简单除以费率后四舍五入。CNY 快照也核对实付与手续费；支付确认的一分钱容差不能将实际不足 ¥10 的订单扩大为达标。

写入锁顺序为配置行、既有 VIP 用户 advisory lock、用户行，再读取订单及确认退款；余额订单变更也取得相同用户锁，领取不反向锁订单。只读查询不持有写锁。活动读取预检查、写事务最终复核和稳定错误映射分别覆盖。

本次不补发历史奖励，不新增历史奖励追回；现有充值成就退款追回、欠款和终身领取规则保持不变。退款后再次达标只恢复资格，不重置领取唯一键。明确未达标时历史幂等回执的返回顺序，并通过只读历史查询已执行操作，不改写旧回执。

新增迁移，不修改已执行旧迁移；不重置余额、回执、退款记录、预算或成长。

原方案初步统计：287 个未删除账号中候选达标 28 个（27 active、1 disabled），33 个已识别零在线充值账号未达标。这些数据本次未查询生产复核，不能当作最终解锁名单。上线前以最终资格函数只读重算，提供仅管理员加余额等受影响老用户清单，不自动把赠送转实付。

后端实施先写失败回归，覆盖金额边界、手续费与赠金、退款各状态、旧单及币种、支付回调重试、两连接并发、全部 API 和卡片分流、账号禁用、现金/预算/名单/终身领取、旧配置缺字段及审计。前端验证锁定、金额、充值跳转、核验失败、支付后刷新、旧页面重锁、历史及佩戴保留。

隔离分支测试后，在 staging 用合成账户验证 9.99→10→消费→退款→再次达标，不用真实生产用户做资金测试。生产部署和资金操作另行确认。

部署后的 `deploy/sql/verify-achievement-recharge-access.sql` 按当前门槛构造“差一分→补足→消费→确认退一分→重锁→再次达标→同日不重复发奖→禁用”的合成链路，全程事务回滚，不调用支付网关、不保留用户或余额变更。

¥10 是准入门槛，入金不等于已经消耗的成本。批量达标和低成本 Token 获奖仍有套利可能。实付消费资格、累计现金奖励上限、预算调整及跨账号风控属于独立后续变更，不未经确认捆绑上线。

依赖安全兼容：前端与画布将 `follow-redirects` 同步升级到兼容补丁 `1.16.2`，修复高危公告 [GHSA-mrwp-f3q8-3g9p](https://github.com/advisories/GHSA-mrwp-f3q8-3g9p)，不新增审计豁免。
