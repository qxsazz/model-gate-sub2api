# HTTP 报错速查

按状态码定位，再根据错误正文判断原因。下面的业务码和消息是项目中的代表性情况，各协议不一定返回相同结构。

## 状态码导航

| 状态 | 含义与处理入口 | 是否直接重试 |
| --- | --- | --- |
| [400](#400-请求格式错误) | 请求格式或参数 | 修正后再试 |
| [401](#401-鉴权失败) | 密钥或账户鉴权 | 先核对凭据和状态 |
| [403](#403-权限与余额) | 权限、余额、过期或 IP | 先处理明确限制 |
| [404](#404-地址与模型) | 地址或模型范围 | 核对协议、路径和模型 |
| [413](#413-请求体过大) | 请求大小超限 | 缩减请求 |
| [429](#429-限流与额度) | 频率、并发、预算或上游限流 | 依据原因和重置时间 |
| [499](#499-请求被取消) | 客户端或请求上下文取消 | 先核对记录 |
| [500](#500-服务内部异常) | 内部处理异常 | 有限重试，持续报错则反馈 |
| [502](#502-上游请求失败) | 上游连接、认证或响应异常 | 按正文判断 |
| [503](#503-服务暂不可用) | 过载或暂时无可用渠道 | 退避，必要时反馈 |
| [504](#504-等待超时) | 上游、代理或异步任务超时 | 核对完成与计费状态后再试 |

## 400 · 请求格式错误

**常见消息：** `Failed to parse request body`、`Request body is empty`、`model is required`、不支持的模型或参数。

| 排查项 | 解决方向 |
| --- | --- |
| JSON 不完整或引号转义错误 | 用 JSON 序列化生成请求体，尤其注意 PowerShell 与 Bash 不同 |
| 缺少 `model`、参数类型不符 | 检查必填字段；例如 `stream` 应使用协议要求的布尔值 |
| 协议与请求体不匹配 | Responses 使用对应的 `input` 格式，Chat Completions 与 Messages 使用各自请求体 |
| 复合分组或模型不支持该入口 | 核对分组能力，不能仅根据模型列表认定所有接口可用 |

不要把网站领取奖励等业务操作的 400 当成模型调用参数错误，见 [账户问题](/docs?cat=troubleshooting&page=account-issues)。

## 401 · 鉴权失败

| 代表性业务码 | 含义 | 解决方向 |
| --- | --- | --- |
| `API_KEY_REQUIRED` | 没有有效提供 API Key | OpenAI 兼容调用检查 Bearer 头；其他协议使用对应鉴权方式 |
| `INVALID_API_KEY` | 密钥无法识别 | 去除多余空格、换行、错误引号；核对是否误用了测试密钥 |
| `API_KEY_DISABLED` | 密钥已停用 | 在密钥页面检查状态，使用已启用、获授权的密钥 |
| `USER_INACTIVE` / `USER_NOT_FOUND` | 关联账户不可用 | 联系平台核对账户，不通过反复更换客户端规避 |

网页登录使用登录会话，模型 API 使用 API Key。不要将网站密码、JWT 或刷新 Token 当作模型密钥。更新临时环境变量后，从设置了变量的终端启动客户端；不是重新打开任意终端就会自动继承。

## 403 · 权限与余额

| 代表性业务码 / 情况 | 解决方向 |
| --- | --- |
| `API_KEY_EXPIRED` | 核对密钥有效期，调整获授权的配置或创建新密钥 |
| `INSUFFICIENT_BALANCE` / `billing_error` | 查看可用余额与具体计费错误；有余额也不代表订阅或额度条件全部满足 |
| `ACCESS_DENIED` | 核对客户端出口 IP 与密钥访问限制，不关闭安全校验 |
| `GROUP_NOT_ALLOWED` | 核对专属分组资格；退款、退费或人工变更可能使旧密钥不再获准使用 |
| `GROUP_DISABLED` / `GROUP_DELETED` | 核对分组状态与公告，选择仍可使用的获授权分组 |
| `SUBSCRIPTION_NOT_FOUND` / `SUBSCRIPTION_INVALID` | 核对该订阅分组是否存在有效订阅，不把账户余额当作订阅资格 |
| 内容安全或访问策略拦截 | 根据响应调整合规请求；无法确认时向平台反馈，不尝试绕过策略 |

不是看到 403 就必须充值。先确定是余额、有效期、IP、分组还是访问策略。

## 404 · 地址与模型

检查客户端是否重复追加 `/v1`，是否把完整接口路径填进 Base URL，是否用了错误的协议地址。

项目的分组模型允许列表也会返回 404，并提示 `Model ... is not available for this group`。用发生错误的同一枚密钥查询 `/v1/models`，核对模型标识、大小写、分组及协议能力。

不支持的模型或路由也可能包装成 400、403 或上游错误，不应只按 404 判断模型存在与否。

## 413 · 请求体过大

减少上传文件、图片大小或数量，缩短历史上下文，避免把大量文件直接内嵌成 Base64。平台入口与上游都可能有请求体限制，具体大小以当前响应和配置为准。

请求体字节超限与模型上下文 Token 超限不是一回事。遇到上下文长度消息时，应缩短上下文和输出目标，不只调整文件格式。

## 429 · 限流与额度

| 类型 | 代表性提示 | 解决方向 |
| --- | --- | --- |
| 并发已满 | `gateway_concurrency_limit` | 减少同时进行的请求，让长请求结束后再发起 |
| 等待队列已满 | `gateway_queue_full` | 停止继续堆积请求，使用客户端任务队列 |
| 用户或分组 RPM | `rate_limit_exceeded` | 降低频率，尊重响应中的 `Retry-After` |
| API Key 总额度 | `API_KEY_QUOTA_EXHAUSTED` 或兼容包装 | 在密钥页面核对额度；等待不会自动增加已耗尽的总预算 |
| 密钥 5 小时、1 天、7 天额度 | 周期额度超限消息 | 按实际窗口重置时间等待或核对额度设置 |
| 用户平台日、周、月额度 | 周期额度超限消息与重置元信息 | 等待相应窗口或核对账户额度，不按一分钟简单重试 |
| 上游限流 | `Upstream rate limit exceeded` 等 | 退避并查看渠道状态，不把全部原因归为自己的 RPM |
| 无效认证请求过多 | `INVALID_AUTH_RATE_LIMITED` | 先修正凭据，停止连续提交无效密钥 |

VIP 并发与 RPM 是不同规则。提升 VIP 不代表能绕过 API Key 预算、分组限制或上游限流。

## 499 · 请求被取消

项目在部分请求上下文取消场景中使用 499；客户端也可能只显示取消或断开连接。检查是否主动停止生成、关闭页面、切换任务，或让客户端超时提前中止。

请求取消不保证此前生成的用量为零。先查看 [使用与错误记录](/docs?cat=troubleshooting&page=records)，再决定是否重新调用。

## 500 · 服务内部异常

`INTERNAL_ERROR` 等表示内部处理失败；API 鉴权、订阅维护或网站接口都可能发生。保存时间、接口、错误正文和请求 ID，短暂异常可有限重试，持续异常应反馈平台。

不要用重复充值、清空全部配置或公开完整密钥作为处理手段。

## 502 · 上游请求失败

本项目会把部分上游 401 / 403 映射为 502，消息可能是 `Upstream authentication failed` 或 `Upstream access forbidden`。这类情况需要平台检查上游渠道，不意味着用户自己提交的 API Key 必然无效。

`Upstream request failed`、异常响应或渠道耗尽也可能表现为 502。先检查 [渠道状态与记录](/docs?cat=troubleshooting&page=records)，用小请求复核；不要高并发重复撞同一故障。

## 503 · 服务暂不可用

| 消息 / 情况 | 解决方向 |
| --- | --- |
| `No available accounts` | 当前分组暂时没有可调度渠道，查看状态或反馈平台 |
| `API_KEY_AUTH_OVERLOADED` | 鉴权服务暂时繁忙，退避后再试 |
| `VIP_UNAVAILABLE` 或会员鉴权暂不可用 | 当前无法确认会员权限，不代表 API Key 无效；稍后重试，不需要重新生成密钥 |
| `billing_service_error` | 计费服务或当前倍率暂时无法确认，等待恢复，不因该错误重复充值；不会因此自动改用原价 |
| 上游过载或服务暂不可用 | 有限退避重试，持续发生时提供脱敏材料 |

暂时无可用渠道不代表模型不存在，也不等于用户缺少会员身份。

## 504 · 等待超时

可能来自上游首段输出等待、代理超时或异步图像任务超时。先减小上下文与任务复杂度，核对客户端等待时间及网络，再查看请求或任务记录。

异步任务提交成功但后续失败，与提交接口立即返回错误不同。重新提交前确认原任务状态，避免产生重复任务。

## 其他返回与包装差异

部分客户端或上游可能出现 402、408、409、422、529 等状态。先读取实际正文和入口，不能套用固定结论。例如站内余额不足通常可表现为 403，上游过载也可能被包装为 503。

流式响应启动后可能保持 HTTP 200，再通过错误事件表示失败，见 [网络与流式异常](/docs?cat=troubleshooting&page=network)。
